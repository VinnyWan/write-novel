# write-novel-review：多视角审查 + 质量管道

你对章节文本执行两阶段质量审查：先并行审查，再串行深度加工。

---

## 审查维度（6 维度，3 Blocking + 3 Warning）

每章审查覆盖 6 个维度：

### Blocking（不通过则不能提交）

| 维度 | 说明 | 数据来源 |
|------|------|---------|
| 1. 事实一致性 | 角色状态、设定、时间线是否与已有 `章节提交记录/*.md` 冲突 | `章节提交记录/`、`世界设定/` |
| 2. 角色 OOC | 行为/对话是否偏离 `人物/*.md` 卡片定义 | `人物/` 目录 |
| 3. 伏笔合规 | 新埋伏笔是否登记，已有伏笔是否有推进/回收 | `伏笔与线索回收池.md` |

### Warning（记录但不阻断）

| 维度 | 说明 |
|------|------|
| 4. 节奏感 | 爽点密度、铺垫/爆发比例、章节钩子有效性 |
| 5. 追读力 | Hook → 爽点 → 微兑现 → 悬疑链，四指标综合评分 |
| 6. AI 味 | AI 写作痕迹检测（禁用词、句式模板、机械化表达） |

### 平台特定评分标准

审查时根据 `全局写作状态.md` 中的 `目标平台` 字段自动加载对应 rubric：

| 平台 | Rubric 文件 | 核心关注点 |
|------|------------|-----------|
| 起点 | `references/rubrics/qidian.md` | 追读率/订阅转化，重爽点密度和章尾钩子 |
| 番茄 | `references/rubrics/fanqie.md` | 完读率/流量，重开头抓人和快节奏 |
| 知乎 | `references/rubrics/zhihu.md` | 短篇反转，重情绪冲击和结尾反转 |

未配置目标平台时默认使用起点标准。

## Phase 1：六维并行审查

Spawn 4 个 Agent（full 模式），覆盖全部 6 个维度。4 个 Agent 同时启动，全部返回后进入综合裁决。

### Agent 1: 事实一致性 + 角色 OOC（Blocking）

审查内容：
- 设定一致性：本章的角色状态/能力/关系是否与已有章节提交记录矛盾？
- 时间线/地点：时间跳转和地点切换是否与前章合理衔接？
- 角色行为一致性：角色言行是否符合 `人物/*.md` 卡片定义？
- 前后矛盾：本章与前章信息是否冲突？

### Agent 2: 伏笔合规（Blocking）

审查内容：
- 新埋伏笔：本章新埋的伏笔是否已登记到 `伏笔与线索回收池.md`？
- 伏笔推进：是否有对已登记伏笔的推进/暗示？
- 伏笔回收：本章是否完成了预期回收的伏笔？逾期伏笔是否有说明？
- 伏笔合理性：新埋伏笔是否有明确的预期回收节点？

### Agent 3: 节奏感 + 追读力（Warning）

审查内容：
- 剧情连贯性：本章事件衔接是否流畅？有无断裂？
- 节奏：场景切换是否流畅？有无拖沓或过快的段落？
- 爽点密度：3000 字内是否有至少一个情绪释放点？
- Hook 有效性：开篇是否抓住注意力？结尾是否有翻页冲动？
- 微兑现：本章是否有小成果/小收获让读者感到进度？
- 悬疑控制：悬疑债是否在合理范围内（不欠太多不还）？

### Agent 4: AI 味（Warning）

审查内容：
- 禁用词检测：是否命中 `全局写作状态.md` 中的高压线禁用词？
- 句式模板化：是否有重复的句式模式？
- AI 套话：是否出现「不仅如此」「更重要的是」「总而言之」等模板化表达？
- 机械化表达：对话是否过于工整、描述是否缺乏个性？

### 综合裁决

4 个 Agent 全部返回后：
1. 按阻断级别分类：
   - **致命/Blocking**（事实矛盾 / 人物 OOC / 伏笔缺失）→ 阻断提交，必须修改
   - **严重/Warning**（节奏问题 / 追读力不足 / AI 味）→ 记录但不阻断
   - **建议**（文风优化 / 对话打磨）→ 仅建议
2. 跨 Agent 去重（同一问题可能被多个 Agent 发现）
3. Blocking 全通过 → 在章节草稿 frontmatter 标记 `审查通过: true`
4. 有 Blocking issue → 返回问题清单，不标记通过

## Phase 2：质量管道串行加工

Phase 1 审查报告生成后，依次启动 3 个 Agent 串行加工。上一轮输出作为下一轮输入。

### Step 1: write-novel-deslop-agent（去 AI 味）

- 输入：正文 + Phase 1 审查报告
- 行为：逐句扫描 AI 痕迹，直接改写输出清洁文本
- 输出：清洁文本 + 修改日志（每处修改的位置和原因）
- 约束：不改变剧情内容、不增删关键信息、保留作者风格

### Step 2: write-novel-senior-editor（资深编辑）

- 输入：清洁文本
- 行为：商业向深度审稿
  - 开篇钩子够不够强？
  - 节奏有没有拖沓或过快？
  - 爽点密度够不够（每 3000 字至少一个）？
  - 人物对话能区分吗？
  - 结尾能让人点下一章吗？
- 输出：审稿意见 + 具体修改建议（每条附位置）

### Step 3: write-novel-picky-reader（挑剔读者）

- 输入：清洁文本 + 编辑意见
- 行为：模拟真实挑剔读者的第一反应
  - 第一句抓住我没有？
  - 前三段我想继续读吗？
  - 哪里让我出戏了？
  - 情绪有没有打到我？
  - 读完我想点下一章吗？
- 输出：读后感（不讲术语，只讲感觉）+ 弃书风险评估（低/中/高 + 理由）

---

## 管道中断规则

任一 Agent 发现致命级别问题时：
1. 该 Agent 在输出中标注致命问题
2. 管道暂停
3. 主线程向用户汇报：「发现致命问题：[问题描述]。建议回炉修改。是否继续管道？」

（deslop-agent 输出）

（picky-reader 输出）
