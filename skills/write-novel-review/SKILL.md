# write-novel-review：多视角审查 + 质量管道

你对章节文本执行两阶段质量审查：先并行审查，再串行深度加工。

---

## Phase 1：四维并行审查

Spawn 4 个 Agent（full 模式），各从单一维度审查。4 个 Agent 同时启动，全部返回后进入综合裁决。

### Agent 1: 结构审查

审查内容：
- 剧情连贯性：本章事件是否与前章衔接？有无断裂？
- 节奏：场景切换是否流畅？有无拖沓或过快的段落？
- 伏笔回收：本章是否完成了应该回收的伏笔？
- 章节钩子：结尾是否有让人想翻下一章的东西？

### Agent 2: 文风审查

审查内容：
- 句式多样性：是否有连续三段以相同方式开头？
- 口语化程度：对话是否自然？
- AI 痕迹：是否命中禁用词表？
- 描写密度：动作/环境/心理描写的比例是否合理？

### Agent 3: 连贯性审查

审查内容：
- 设定一致性：角色能力是否超出设定边界？
- 角色行为一致性：角色行为是否符合其人设？
- 时间线/地点：时间跳转和地点切换是否合理？
- 前后矛盾：本章与前章信息是否矛盾？

### Agent 4: 爽点审查

审查内容：
- 情绪递送：本章交付了什么情绪？是否有效？
- 期待感控制：钩子是否拉满？
- 高潮有效性：高潮段落是否有足够的冲击力？
- 爽点密度：3000 字内是否有至少一个情绪释放点？

### 综合裁决

4 个 Agent 全部返回后：
1. 按严重性分级：**致命**（剧情逻辑断裂/人设崩塌）> **严重**（节奏问题/连贯性不足）> **建议**（文风优化/对话打磨）
2. 跨 Agent 去重（同一问题可能被多个 Agent 发现）
3. 输出统一审查摘要

---

## Phase 2：质量管道串行加工

Phase 1 审查报告生成后，依次启动 3 个 Agent 串行加工。上一轮输出作为下一轮输入。

### Step 1: write-novel-deslop-agent（去 AI 味）

- 输入：正文 + Phase 1 审查报告
- 行为：逐句扫描 AI 痕迹，直接改写输出清洁文本
- 输出：清洁文本 + 修改日志（每处修改的位置和原因）
- 约束：不改变剧情内容、不增删关键信息、保留作者风格

### Step 2: write-novel-senior-editor（资深编辑）

- 输入：清洁文本
- 行为：商业向深度审稿
  - 开篇钩子够不够强？
  - 节奏有没有拖沓或过快？
  - 爽点密度够不够（每 3000 字至少一个）？
  - 人物对话能区分吗？
  - 结尾能让人点下一章吗？
- 输出：审稿意见 + 具体修改建议（每条附位置）

### Step 3: write-novel-picky-reader（挑剔读者）

- 输入：清洁文本 + 编辑意见
- 行为：模拟真实挑剔读者的第一反应
  - 第一句抓住我没有？
  - 前三段我想继续读吗？
  - 哪里让我出戏了？
  - 情绪有没有打到我？
  - 读完我想点下一章吗？
- 输出：读后感（不讲术语，只讲感觉）+ 弃书风险评估（低/中/高 + 理由）

---

## 管道中断规则

任一 Agent 发现致命级别问题时：
1. 该 Agent 在输出中标注致命问题
2. 管道暂停
3. 主线程向用户汇报：「发现致命问题：[问题描述]。建议回炉修改。是否继续管道？」

```
- 连贯性：N 个问题
- 爽点：N 个问题

### Phase 2: 去 AI 味修改日志
（deslop-agent 输出）

### Phase 3: 编辑审稿意见

（picky-reader 输出）

### 综合评估
- 弃书风险：低/中/高
- 是否建议发布：是/否（理由）
- 优先修改项：Top 3
```
