# 投影管线规范

## 概述

章末 CHAPTER_COMMIT 后，系统自动驱动多目标投影管线，将本章产生的事实变更增量同步到各追踪目标。

## 投影前置条件

- CHAPTER_COMMIT 文件已创建（`.story-system/commits/chapter_{N}.commit.md`）
- 合约文件存在且通过 Precommit Gate
- 正文文件已落盘

## 4 个投影目标（分 2 组并行执行）

投影分两组并行执行，组间无文件依赖：

**并行组 1**：state + index（写入 `追踪/角色状态.md` 和 `追踪/索引.md`）
**并行组 2**：summary + memory（写入 `追踪/章节摘要/第{N}章.md` 和 `追踪/写作记忆.md`）

> 无法并行时（如环境限制），回退到串行顺序：state → index → summary → memory。

### 1. state — 角色状态投影

**产出文件**：`追踪/角色状态.md`（增量更新）
**执行组**：并行组 1

**提取规则**：
- 扫描本章正文，识别以下变更类型：
  - 新角色出场（标记首次出现章、角色、当前状态）
  - 已有角色状态变化（身份变更、能力变化、关系变化、位置变化、情绪转折）
  - 角色离开/死亡（标记离开章、原因）
- 每种变更追加到对应角色的条目下，附来源章节号
- 不重复登记已在追踪文件中的相同状态

**更新格式**：
```markdown
### {角色名}
- [第{N}章] {变更描述} — 来源：第{N}章正文
```

### 2. index — 索引投影

**产出文件**：`追踪/索引.md`（增量更新）
**执行组**：并行组 1

**提取规则**：
- 新实体：本章新出现的具名物品、地点、组织、概念 → 追加到对应分类
- 新关系：本章建立的角色/势力间新关系 → 追加关系条目
- 新伏笔：本章新埋设的伏笔 → 追加到伏笔索引，标记 `status: open`
- 伏笔回收：本章回收的伏笔 → 更新对应伏笔条目 `status: recycled`

**更新格式**：
```markdown
## 物品
- {物品名}：{简述}（首现：第{N}章）

## 地点
- {地点名}：{简述}（首现：第{N}章）

## 伏笔
- {伏笔描述}：status=open | recycled, 来源=第{N}章
```

### 3. summary — 章节摘要投影

**产出文件**：`追踪/章节摘要/第{N}章.md`（新建）
**执行组**：并行组 2

**提取规则**：
- 3-5 句情节摘要（概括本章核心事件）
- 关键情节点列表（3-8 条，bullet）
- 出场角色列表（含角色名 + 本章角色功能）
- 与前后章连接（前章回扣 + 后章伏笔）

**输出格式**：
```markdown
# 第{N}章摘要

## 情节摘要
{3-5句连贯叙述}

## 关键情节点
- {情节点1}
- {情节点2}
- ...

## 出场角色
- {角色名}：{本章功能/状态}

## 连接
- 前章回扣：{上一章相关事件}
- 后章伏笔：{为下一章埋下的线索}
```

### 4. memory — 写作记忆投影

**产出文件**：`追踪/写作记忆.md`（增量更新）
**执行组**：并行组 2

**提取规则**：
- 从本章识别成功的写作模式（可选，仅在确认有价值时记录）：
  - 有效的钩子结构
  - 成功的节奏序列
  - 出色的对话交锋
  - 爽点释放模式
  - 情绪递进方式
- 记录模式类型、来源章、简短说明
- 与 `project_memory.json` 的模式学习系统联动

## 日更精简投影

日更模式（workflow-daily）使用精简投影：仅执行并行组 1 的 state 和并行组 2 的 summary（2 目标），跳过 index 和 memory。详见 workflow-daily.md。

## 投影日志

两组投影完成后，追加一行到 `追踪/projection-log.jsonl`：

```json
{"chapter": 42, "timestamp": "2026-06-18T15:30:00", "targets": {"state": "success", "index": "success", "summary": "success", "memory": "success"}, "mode": "parallel"}
```

> `mode` 字段：实际执行模式 — `parallel`（并行）或 `serial`（串行回退）。

## 失败处理

- 单组失败：另一组结果保留，commit 标记为 `projection_status: partial`
- 组内单目标失败：同组另一目标正常完成，该组标记部分成功
- 两组全部失败：commit 标记为 `projection_status: failed`，记录详细错误
- 投影失败不阻塞下一章写作

## agent 执行说明

投影管线由主线程 agent 在 Postcommit Gate（Stage G）中执行。两组投影可并行启动（如环境支持），不 spawn 子 agent。每组完成后立即验证文件写入成功。
