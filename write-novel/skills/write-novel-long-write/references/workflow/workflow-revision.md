# 大修/回炉流程

## 触发条件

用户输入包含"修改第X章""回炉""重写第X章"。

## 流程

### 步骤 1：定位目标章节

1. 解析用户输入中的章节编号（如"修改第3章" → 第3章）
2. 确认目标章节正文存在：`章节草稿/第{章序号}章_{标题}.md`
3. 确认目标章节细纲存在：`分卷大纲/第{卷序号}卷_细纲_第{章序号}章.md`

### 步骤 2：确认修改原因

问用户：
- 为什么要改这章？（剧情走向不对 / 角色写崩了 / 节奏不好 / 文笔需要提升 / 去AI味）
- 只改这一章还是连带后续一起调？

### 步骤 3：加载上下文

1. 读取目标章节细纲（确认硬性剧本任务是否还适用）
2. 读取目标章节正文（定位问题段落）
3. 读取前一章摘要（连贯性基准）
4. 解析本章涉及的角色卡片和伏笔状态
5. 读取全局写作状态中的系统提示词和高压线

### 步骤 4：重写

#### 局部修改（不改剧情）

- 用户指定修改范围 → 只修改指定段落
- 保持其他内容不变
- 修改后检查与前后章的连贯性

#### 全面重写（改剧情走向）

- 先确认细纲是否需要同步修改
- 如果细纲变更，更新细纲的硬性剧本任务
- 重写后重新执行续航闭环：
  - 覆盖旧正文
  - 重新生成摘要
  - 更新涉及角色的状态（如果状态变化）
  - 更新伏笔追踪（如果伏笔内容变化）

### 步骤 5：更新关联内容

如果修改影响了后续章节的连续性：
- 提示用户需要检查的后续章节列表
- 让用户决定是否级联修改

### 步骤 6：验证

- 检查修改后章节与前后章的衔接
- 检查角色状态一致性（修改章的角色状态是否与前后章矛盾）
- 检查伏笔连续性（如果修改了伏笔相关内容）

## 注意事项

- 修改时保留上一章的尾声状态作为起点
- 角色能力不得超出设定文件定义范围
- 如果修改涉及新角色/新设定，在章节末尾标注
