# analyze-common：拆文共享门控与机制

两套 scope（long/short）共用的质量门控、恢复机制和分块策略。

---

## 恢复机制

### Long scope

1. 管道启动时检查 `_progress.md`
2. 如有，读取断点信息（最后处理章节 + 当前阶段 + 最终状态）
3. 断点状态为 `paused_after_stage1` → 跳过 Stage 0/1，从 Stage 2 续跑
4. 其他断点状态 → 从断点所在块的起始章节恢复，覆盖该块已有输出

### Short scope

1. 管道启动时检查 `_meta.json`
2. 存在 → AskUserQuestion 三选一：
   - (a) 覆盖：归档旧产出后从 Stage 2 重跑
   - (b) 续跑：从 `last_stage_in_progress` 或 `stages_completed[]` max+1 续跑
   - (c) 取消
3. 不存在 → 直接进入新一轮拆解

---

## 质量门控概要

### Long scope

Stage 3-4 完成前需通过质量检查：
- 置信度 ≥ 0.85
- 覆盖率 85%-95%
- 重叠率 ≤ 35%

Stage 3-5 还须过「事实可溯源」自检：硬事实必须能 grep 回原文，原文没给的写「原文未明确」。

### Short scope

Phase 7 三道门控：
1. **7.1 拆文报告 AI 腔自检**：扫描 `拆文报告.md`（跳过原文引用），命中 banned-words 或 AI 句式 → 阻断
2. **7.2 `_meta.json.structure_counts` 数值校验**：最低值检查
3. **7.3 `output-templates.md` [BLOCK] 项扫描**：任一缺失 → 阻断

---

## 部分失败容忍

单章/单阶段失败不阻断管道，记入进度文件「失败记录」表：
- `| 类型 | 章节/阶段 | 错误信息 | 重试状态 |`
- 最终状态可为 `completed_with_errors`（报告中注明失败详情）

---

## 事实可溯源自检（共享）

所有硬事实（等级/数值/距离/属性/势力数/出场章/谁说的话）必须能 grep 回原文：
- 原文有明确说明 → 引用出处
- 原文未明确 → 写「原文未明确」，禁推断填空
- 推断项 → 标注「推断：{依据}」

---

## 字数探针（共享）

拿到原文后立刻数字数。实现：优先使用 Read 工具获取全文 → Python 字符统计（包含中文字符、标点，不含 ASCII 空白）。
