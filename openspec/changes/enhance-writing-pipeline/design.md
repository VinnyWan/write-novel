## Context

当前 `story-long-write` 的 5 个 Phase 覆盖了从选题到正文的完整链路，但五个关键创作环节存在结构性不足：
- 世界观/题材构建分散在 Phase 2 中通过 story-architect agent 执行，初始化阶段（story-setup）只做基础设施部署
- 角色设计跨 Phase 2 和 Phase 3b 两次执行，羁绊关系被动记录而非主动设计
- 卷纲/细纲层缺少主线支线的显式追踪
- 细纲 frontmatter 字段偏重合约约束，缺少叙事三要素（事件/冲突/转折点）
- 正文写作与细纲的关系是"校验合规"而非"结构对位"

本次设计在现有 pipeline 上增量增强，不改变 Phase 间的调用顺序和 agent 职责边界。

## Goals / Non-Goals

**Goals:**
- 在 story-setup 中嵌入世界观初始化环节，产出 `设定/世界观.md` + `设定/题材定位.md`
- 在 story-long-write Phase 2 中将角色设计集中化，一次产出主角/配角/羁绊图
- 在 Phase 3a 增加剧情线梳理，产出 `大纲/剧情线.md`，卷纲/细纲标注剧情线
- 细纲 frontmatter 增加三要素字段（event/conflict/turning_point），正文合约从模糊变可校验
- Phase 4 增加细纲拆段→逐段写作校验闭环

**Non-Goals:**
- 不改变 Phase 间调用顺序和 agent 职责边界
- 不新增 agent（复用现有 story-architect / character-designer / narrative-writer / reviewer）
- 不修改短篇流水线（story-short-write）
- 不修改 hooks 和 dashboard

## Decisions

### D1: 世界观初始化嵌入 story-setup Phase 1.5 之后

新增 Phase 1.6：在配置向导完成后，由 story-architect agent 产出世界观和题材定位文件。

**理由**：世界观是后续所有创作的"物理常数"，后移到 Phase 2 会导致 Phase 2 产出物互相依赖（角色需要世界背景，大纲需要世界观约束）。前移到初始化阶段让后续 Phase 可以直接加载世界观上下文。

**替代方案**：保持现状在 Phase 2 构建 → 拒绝，因为 Phase 2 加载的上下文已很多（角色+大纲+设定），加世界观会拖慢单次响应。

### D2: 角色设计在 Phase 2 集中执行

Phase 2 当前分"核心设定"和"设定补全（Phase 3b 末尾）"两次角色建档。改为 Phase 2 一次性完成：主角完整卡 + 核心配角卡（含关系）+ 羁绊图。

Phase 3b 的角色建档改为"增量补全"——只为新出场的次要角色建简化卡，不重复触碰已建角色。

**理由**：角色关系（羁绊）需要所有角色同时在上下文中才能设计，分两次执行会导致第二次设计时第一次的角色信息不在上下文缓存中，关系设计质量下降。

### D3: 剧情线作为独立追踪维度

新增 `大纲/剧情线.md` 文件，结构为：主线 1 条 + 支线 2-5 条，每条含：
- 线名 / 类型（主线/支线）/ 起止卷
- 核心冲突 / 关键节点列表（卷:章 粒度）
- 状态（未开始/推进中/已完成）

细纲 frontmatter 增加 `strand` 字段（已有此字段，强化为必填），卷纲增加每卷的剧情线推进摘要。

**理由**：长篇网文最常见的结构问题是"支线消失"或"主线模糊"。显式追踪让 reviewer agent 可以自动检测支线是否长期未推进。

### D4: 细纲三要素作为核心合约字段

细纲 frontmatter 新增三个必填字段：

```yaml
event: "主角在拍卖会上以低于市价拍得神秘残图，引发各方觊觎"
conflict:
  type: "利益争夺"  # 利益争夺/理念冲突/情感纠葛/生存危机/信息不对称
  parties: ["主角", "血煞宗", "天机阁"]
  intensity: 4  # 1-5
turning_point:
  is_turning: true
  type: "剧情方向"  # 人物弧线/剧情方向/势力格局/世界观揭示
  description: "主角从隐忍转为主动出击"
```

**理由**：现有字段（cbn/cpns/cen）虽然覆盖了爽点维度，但缺少叙事结构的核心描述。三要素是编辑视角的基本单位，让 reviewer 可以自动化检测"这章有没有事件""冲突够不够""转折点是否合理"。

### D5: 细纲拆段→逐段写作→覆盖率校验

Phase 4 Stage B（Prewrite Gate）增加"细纲拆段"步骤：
- 将细纲的三要素拆分为 3-6 个写作段落
- 每段标注：预期字数 / 叙事功能（铺垫/推进/爆发/余韵）/ 对应的事件或冲突点

Stage C 正文执行时按段输出，每段用 `---` 分隔。

Stage E（Postwrite Gate）增加"段落覆盖率"校验：检查实际段数与计划段数是否匹配、每段叙事功能是否完成。

**理由**：这是网文"章末卡高潮"问题的根因——作者写正文时偏离了细纲的节奏设计。拆段机制把细纲的叙事节奏锁定到段落级，减少正文写作时的自由度漂移。

## Risks / Trade-offs

- **初始化变慢**：story-setup 从纯部署变为部署+创作（预计从 2 分钟增至 5-10 分钟），但换来后续 Phase 加载更精准，总体时间不增。→ 按字数分级（100万字以下简化世界观模板）。
- **Phase 2 角色集中化变重**：一次产出所有角色卡+羁绊图可能使 Phase 2 时间显著增加。→ 按字数分级（100万字以上完整角色卡，100万字以下简化卡），配角数量上限=字数/20万（即200万字最多10个核心配角）。
- **剧情线追踪增加细纲维护成本**：每章细纲需标注 strand，写正文时需更新剧情线推进状态。→ 日更模式下 strand 标注可选，精修模式下必填。
- **细纲拆段可能限制创作灵活性**：过于严格的段落规划可能让正文变得机械。→ 拆段是"建议"而非"强制"，Stage C 可以适度偏离，Stage E 只校验偏离是否超过阈值（段落数差异±1 以内、覆盖率 >= 80%）。

## Migration Plan

1. **模板更新**：新增 `设定/世界观.md`、`设定/题材定位.md`、`大纲/剧情线.md` 模板；更新 `大纲/细纲_第X章.md` 模板增加三要素字段
2. **Skill 更新**：`story-setup/SKILL.md` 增加 Phase 1.6；`story-long-write/SKILL.md` 调整 Phase 2/3a/3b/4 描述
3. **Agent 更新**：`story-architect` 增加世界观构建和剧情线设计指引；`character-designer` 增加羁绊图输出格式；`narrative-writer` 增加分段写作指引；`reviewer` 增加三要素校验规则
4. **向后兼容**：已有的 `.story-config.json` 和 `设定/` 目录下旧文件不强制迁移，新书自动使用新流程
5. **回滚**：如 Phase 1.6 导致 setup 过重，可将其降级为可选（`--skip-worldbuilding` 标志）
